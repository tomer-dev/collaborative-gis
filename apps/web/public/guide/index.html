03 / 15 · the demo

What to do in five minutes

Two accounts, two windows. Each step below is a screenshot from the running app (local, seeded with 50 areas).

To run it yourself: README › Setup (Docker PostGIS, pnpm install, migrate, pnpm dev).

  1. Register. Name, email, a password of 8 characters or more. You land on the map, signed in.

  2. Draw. Press the polygon button, click vertices. The New area panel shows the area in km² and the vertex count as you go.

  3. Open a second window with the other account. The first user's draft appears there as a dashed ghost in their colour, and the presence list says who is drawing.

  4. Save. Finish, give it a name. The dialog shows the client estimate; the server measures with PostGIS and both windows get the saved polygon.

  5. Rename, then revert. History lists every version. Reverting to version 1 creates version 3 with version 1's content; nothing is deleted.

  6. Switch to aerial imagery. The polygon stays on the same ground. govmap has no imagery over the sea, which renders black.

If something looks wrong: GET /readyz reports the database, the Room and the configuration; the API reference is at /docs.

04 / 15 · the backend

Backend core

One Worker serves the API, the static app and the WebSocket upgrade. Live collaboration runs in the Room: a single Cloudflare Durable Object (one stateful instance with its own storage) that holds every open socket, each user's draft and the presence list. Areas live in PostGIS.

  • DoneWebSocket server for real-time updates
  • Doneendpoints for: saving drawn areas with metadata (area name, size calculation)
  • Partialretrieving all areas within current map bounds: at most 500 per 0.1° tile, no truncation flag (see 12)
  • Doneuser authentication and session management
  • Donearea versioning and edit history
  • Donecalculate and return the area size in square kilometers
  • Donehandle concurrent drawing from multiple users

Concurrent drawing

Each user has one draft in the Room's SQLite. Frames from one user run in order in a per-user queue; the Room relays them to everyone else and never back to the sender. Two users on the same area resolve by version (section 04).

06 / 15 · the database

Database design and performance

PostGIS 3.6 on PostgreSQL 18. Geometry stays in the database; the API reads explicit columns through the query builder and only uses raw SQL for PostGIS fragments and the write CTEs.

  • Doneefficient schema for geospatial data
  • Donemigrations
  • Doneproper indexing for spatial queries
  • Partialhandle large datasets (10,000+ polygons per map region): a region is never served whole (see 12)
  • Donesoft deletes and data retention policies

Schema, in short

areas          id, name, geom geometry(Polygon, 4326),
               area_km2, version, created_by,
               created_at, updated_at, deleted_at
               GiST(geom) WHERE deleted_at IS NULL
area_versions  PK (area_id, version): name, geom,
               area_km2, changed_by, changed_at
audit_log      user_id, action, entity, entity_id,
               version, ip, user_agent, request_id,
               at, details (redacted)
+ Better Auth  user, session, account, verification
migrations     0000_postgis … 0005_audit_request_id

Soft delete sets deleted_at and bumps the version. A daily cron purges areas deleted more than 7 days ago with their versions, in batches, and writes an audit row per batch.

07 / 15 · security

Security and reliability

Every input is parsed at the boundary, every response carries the same headers and a request id, and every error has a fixed shape.

  • Doneinput sanitization and validation
  • DoneCORS configuration
  • Doneproper error logging and monitoring
  • Donerequest timeout handling
  • Donesecure WebSocket connections with authentication tokens

Hono's secure headers on every response. The request id is server-generated and appears on every log line of that request.

The WebSocket gate

An upgrade needs the Better Auth session cookie (else 401) and an Origin equal to CLIENT_ORIGIN (else 403) before the Room sees it. The Worker passes the user to the Room in server-set headers and overwrites any copy the client sent. Cookies are __Secure-, HttpOnly, SameSite=Lax once deployed; the socket is wss:.

Honest limitations

The capability matrix, capability-matrix.md (2026-10-13), marked 5 of 78 capabilities as partial. Since then docker-compose became done (PR #67) and the independent feature check, codex-check.md (267deb2), moved smooth layer transition to partial: 5 partial items, 6 cards. One card each: the capability, what is delivered, what is missing, and where to look.

Retrieving all areas within current map bounds

Delivered
GET /api/areas?bbox=… over a partial GiST index, a per-tile cache with an ETag, and the list and polygons in the UI.
Missing
The query returns at most the 500 most recently updated areas of the snapped 0.1° tile, with no truncation flag and no paging, so a denser tile silently drops areas, possibly ones inside the viewport.
Where
apps/api/src/db/spatial-read.ts · LIMITS.BOUNDS_LIMIT in packages/shared/src/constants/limits.ts

Log all user actions for audit trail and analytics

Delivered
audit_log rows for area create, update, delete and revert (in the write's transaction), each saved draft, sign-in, sign-up, sign-out and failed sign-in, every 422 and 429, and each purge run; viewport reads as JSON log lines.
Missing
The Room writes no audit rows, so WebSocket joins, leaves, presence changes and draft sessions that are never saved or are refused leave no per-user record; audit_log has no index and no retention.
Where
apps/api/src/middleware/audit.ts · apps/api/src/do/ (no audit writer) · README, Security measures

Handle large datasets (10,000+ polygons per map region)

Delivered
A seed to 10,000 rows; the bounds query at that size runs in 0.22 ms p95 on the index; k6 reads at 86 ms p95 end to end.
Missing
The 10,000 were spread over all of Israel (30 inside the benchmark viewport). A region that holds 10,000 is never served whole: each read stops at 500 per tile, and there is no zoom simplification, clustering or paging (zoom is accepted and ignored).
Where
apps/api/src/cache/bounds.ts · docs/benchmarks.md · apps/api/src/db/seed.ts

Smooth layer transition

Delivered
A 300 ms crossfade of the new base layer over a still copy of the old tiles, skipped under reduced motion; layer-switch.test.ts asserts the animation and the snapshot.
Missing
The old-layer snapshot is removed when the animation ends, not when the new tiles have loaded, so slow tile loads can show a gap (feature check at 267deb2).
Where
apps/web/src/lib/geo/layer-switch.ts · docs/adr/0005

Message queuing for high-volume WebSocket traffic

Delivered
No queue. Related, but not a queue: the Room handles one user's frames in arrival order, the client holds frames until the socket opens, frames are capped at 10/s per socket, and frame metrics are batched.
Missing
No delivery queue: fan-out writes directly to sockets and failed sends are logged; Cloudflare Queues are in the ADR-0004 growth path, not built.
Where
apps/api/src/do/sockets.ts · apps/api/src/do/room.ts · docs/adr/0004

Docker containerization with docker-compose (optional): done since PR #67

Delivered
docker-compose.yml runs PostGIS 18 / 3.6 on a loopback port with a health check and, since PR #67 (merged 2026-10-13), an api service that runs the Worker under wrangler dev in a container (apps/api/Dockerfile.dev). Also known, in one line each

  • The 50-per-minute limit counts REST writes and draft sessions, not frames (D5; D-numbers are entries in the design spec's decision log, section 15): one tab can send up to 600 frames a minute under the separate 10/s cap.
  • Aerial imagery depends on govmap's legacy tile cache (newest tiles 2024-01), which can be retired without notice; there is no fallback imagery. The aerial e2e specs need the internet and run locally only.
  • “No third-party plugins for the collaborative features” is read narrowly (D25): drawing adapts leaflet-editable, and area and self-intersection use @turf; the presence, relay, fan-out and limiter code is this repository's.
  • Switching base layers maps to the nearest resolution, so a round trip can change the zoom (z15 → L07 → z16).
  • Load was measured locally at 10 REST users and 5 sockets, never against production and not at the 50 to 100 users the spec planned.
  • Realtime is one Room for the whole app (D11). An area event between a viewport's first read and the socket's join is picked up at the next pan or reconnect.
  • A session revoked elsewhere keeps working for up to 5 minutes where its cookie cache is still valid (D24). Deploying needs Workers Paid (D21). The sign-in limiter counts per Worker instance (isolate), so it is not global.
  • The WAF rule and the Cloudflare health check with its alert are dashboard steps (docs/deploy.md); the repository cannot show them. Cross-region Room placement is untested.
  • Not built from the roadmap: a Neon branch and preview URL per pull request (7.3).
  • History shows only the newest 200 versions of an area, with no pagination.
  • Viewport reads use grid-expanded bounds and bounding-box comparison, so a few areas just outside the viewport can be returned.
  • If the cache invalidation (the map-version bump) fails and the fan-out does not repair it, an old tile can stay readable for up to 30 s.
