Design system proposal — "Grid 4"

One recommended system for Collaborative GIS. Loose constraints on purpose: every rule below exists to stop random sizes, fonts and colours. Decide D15–D18 at the bottom. 2026-10-12.

For a 5-year-old: every Lego brick is a multiple of one stud. Our stud is 4 pixels. You can build with 1, 2, 3, 4, 6, 8 studs… but never a brick and a half. Colours come from one small crayon box, and every crayon has a light and a dark version so the drawing works at night too.

1. Base unit and spacing

Base unit: 4 px. Every spacing, size, radius and line-height is a whole multiple of 4. Allowed spacing steps (Tailwind names → px):

0 · 1=4 · 2=8 · 3=12 · 4=16 · 5=20 · 6=24 · 8=32 · 10=40 · 12=48 · 16=64 · 20=80 · 24=96. Nothing else exists: Tailwind's default open-ended --spacing multiplier is disabled and only these steps are defined, so p-5.5 or w-[23px] fail lint.

Control heights: sm 32 · md 40 · lg 48. Icons: 16 · 20 · 24. Radius: 4 · 8 · 12 · full. Borders: 1 · 2. Hit targets: ≥ 40 × 40 (map handles: 12 px dot inside a 24 px hit area, hidden hit ring).

2. Typography

One family: Inter (variable, self-hosted via @fontsource-variable/inter 5.3.0; no runtime font requests) for UI; ui-monospace for coordinates and ids. Weights: 400, 500, 600 only.

xs 12/16 — captions, coordinate readouts
sm 14/20 — body in panels, table cells, buttons
md 16/24 — default body, inputs
lg 20/28 — section titles
xl 24/32 — page titles
2xl 32/40 — hero number (area readout)

Six sizes, line-heights on the 4 px grid, no fractional sizes, no letter-spacing tricks. Tabular numbers (font-variant-numeric: tabular-nums) for the km² readout so digits do not jump while drawing.

5. Components for M1 (the whole set, nothing speculative)

Button (primary · secondary · ghost · danger × sm/md/lg, with icon slot) · Input + Field (label, hint, error) · Dialog (save, conflict) · Banner (connection state: ok/warn/danger) · Avatar + PresenceList · Panel (side panel shell) · MapControl (Leaflet control wrapper) · Stat (the km² hero number) · Tooltip.

Each component: Tailwind classes from tokens only, cva-style variant map, forwardRef, keyboard & ARIA per WAI-APG, one story file.

6. Enforcement (so it stays a system)

  1. Tokens live in one place: apps/web/src/styles/tokens.css as a Tailwind 4 @theme block. Tailwind's default palette and open spacing are reset (--color-*: initial; --spacing: initial;) so only our tokens generate utilities. docs/constants.md links to it.
  2. Lint: ESLint rule forbidding arbitrary values in className (/\[[^\]]*(px|rem|#)[^\]]*\]/) and raw hex in TSX; eslint-plugin-storybook.
  3. Storybook 10.6.1 (@storybook/react-vite, addon-docs, addon-a11y, addon-vitest, addon-themes): Foundations pages (Spacing, Typography, Colour, Map tokens) rendered from the token file, one CSF3 story file per component with states, play functions for interactive ones, a11y.test: 'error' project-wide, light/dark toolbar via withThemeByClassName. Stories run as browser tests in CI via the vitest addon.
  4. Review rule: a literal size, font or colour in a component is a finding (same rule as hardcoded values).

Where it lives: apps/web/src/ui/* + apps/web/.storybook/* (no separate package until a second consumer exists).

7. Decisions for you

D15 — Adopt "Grid 4" as proposed? Alternatives: 8 px base (coarser, fewer steps; cramped for map controls) or keep Tailwind defaults (open-ended, no enforcement). Recommended: adopt.

D16 — Font: Inter self-hosted (recommended: consistent across OS, tabular numbers, 1 file ~100 KB) vs system-ui stack (zero bytes, inconsistent metrics).

D17 — Primary hue: blue as shown (neutral for a map, distinct from the OSM palette) vs teal/green (clashes with vegetation on aerial imagery) vs let you pick a hex and the ramp is generated.

D18 — Storybook scope: full (foundations + components + vitest browser tests in CI, ~1 extra lane task in M1 wave 2) vs minimal (component stories only, no CI run; tests added in M3).
