# Collaborative GIS — design spec

Date: 2026-10-12. Status: **approved 2026-10-12 after a section-by-section human review** (§2–§9 each acknowledged in `docs/decisions-brief.html`); decisions D1–D14 resolved (see §10). Source brief: Snapland home assignment. Roadmap: `docs/roadmap.md` (Linear P-TOM-1). Research: `docs/research-notes.md`.

## 1. Goal and success criteria

Multiple signed-in users draw polygons on a Leaflet map, see each other's drawing live, switch between OpenStreetMap and govmap aerial imagery without overlays drifting, and get an accurate area in km² for each polygon. The system survives WebSocket loss, limits abuse, keeps history, and runs on Cloudflare with PostGIS on Neon.

Success: a reviewer can clone, run `docker compose up` or `wrangler dev`, open two browsers, and watch one draw while the other sees it; every evaluation criterion in the brief maps to a ticket and to a README section.

## 2. Architecture

```
Browser (Vite SPA: React, TanStack Router/Query, Leaflet 1.9.4)
   │ HTTPS /api/*            │ WSS /ws?map=<id>
   ▼                         ▼
Cloudflare Worker (Hono) ────► Room Durable Object (one per map)
   │ requireUser (Better Auth)   • WebSocket Hibernation API
   │ Zod validation             • presence in socket attachments
   │ RateLimiter DO (per user)  • draft deltas rebroadcast
   │ Cache API (bbox tiles)     • area:* fan-out via RPC
   ▼                            • alarms: stale drafts, reaping
Hyperdrive ──► Neon Postgres + PostGIS
   • areas geometry(Polygon,4326), GiST
   • area_versions, audit_log, auth tables
Cron Trigger ──► retention purge
Static assets (Vite build) served by the same Worker
```

One deployable unit: a single Worker with two Durable Object classes and static assets. Local parity: `wrangler dev` with a Hyperdrive `localConnectionString` to a docker PostGIS, and docker-compose runs PostGIS plus a `wrangler dev` (workerd) container for the one-command bonus; no Node port of the Worker (D9). The Hono CLI (`@hono/cli`) inspects and tests the app in-process (`hono routes`, `hono request`, `hono batch`) with local Cloudflare bindings injected.

## 3. Components and boundaries

| Component | Responsibility | Interface | Depends on |
|---|---|---|---|
| `packages/shared` | Zod schemas and types: Area, AreaVersion, BoundsQuery, ApiError, WS envelope and events, polygon rules | TypeScript exports | — |
| `apps/api` Hono app | REST routes, auth mounting, validation, error shape, cache, audit, OpenAPI | HTTP `/api/*`, `/healthz`, `/readyz`, `/openapi.json` | shared, db, auth, DOs |
| `apps/api` `db/` | Drizzle schema, migrations, spatial SQL helpers (`ST_Area`, `ST_IsValid`, `ST_MakeEnvelope`) | functions taking a `pg` client | Hyperdrive |
| `apps/api` `auth.ts` | Better Auth instance (email+password, Drizzle adapter, trustedOrigins) | `auth.handler`, `auth.api.getSession` | db |
| `Room` DO | WS accept, protocol handlers, presence, draft broadcast, fan-out, alarms | `fetch(upgrade)`, RPC `broadcast(event)` | shared, RateLimiter |
| `RateLimiter` DO | exact sliding window 50/60 s per user | RPC `take(action) → {ok, retryAfter}` | — |
| `apps/web` | routes, auth pages, map (Leaflet 1.9.4), draw tool as a Leaflet `Handler` (D25: no third-party plugins for collaborative features), layer switch as a `Control`, data layer, WS hook, panel | browser | shared |
| `scheduled` handler | retention purge | Cron Trigger | db |

Rule: the Worker never holds state between requests; all coordination state lives in a Durable Object or in Postgres.

## 4. Data model

- `areas(id uuid pk, name text, geom geometry(Polygon,4326) not null, area_km2 numeric not null, version int not null default 1, created_by, created_at, updated_at, deleted_at null)`. GiST on `geom` where `deleted_at is null`.
- `area_versions(area_id, version, geom, name, area_km2, changed_by, changed_at)` pk `(area_id, version)`.
- `audit_log(id, user_id, action, entity, entity_id, version null, ip, user_agent, at)`. Append-only event stream for every user action (mutations, auth events, WS draw sessions, rate-limit and validation rejections). For area events `(entity_id, version)` points at the `area_versions` row that holds the payload; no payload hash. Reads (bounds queries) go to structured Workers Logs, not the table.
- Better Auth tables generated by its CLI.
- Area in km² = `ST_Area(geom::geography) / 1e6` (spheroid). Validity = `ST_IsValid(geom)`; reason returned on failure.

## 5. Data flows

**Save polygon.** Client validates ring (closed, ≥3 unique vertices, ≤1,000, no self-intersection via a simple segment check) → `POST /areas` → Zod → `requireUser` → `RateLimiter.take('draw')` → transaction: insert area with computed `area_km2`, insert version 1, audit row → response → `ctx.waitUntil(room.broadcast({type:'area:created', area}))`.

**Concurrent edit.** `PUT /areas/:id` carries `version`. `UPDATE … WHERE id=$1 AND version=$2 AND deleted_at IS NULL`; zero rows → 409 with the current server row. Client shows a two-button prompt: Overwrite with mine (resend with the server version) or Load theirs. Success bumps version and writes a version row.

**Live drawing.** Client sends `draft:update` deltas (≤10/s, `seq`). Room DO validates, calls `RateLimiter.take`, rebroadcasts to peers except sender. Peers render ghost polygons. On `join` the DO sends the presence list and current drafts.

**Viewport fetch.** `GET /areas?bbox=w,s,e,n&zoom=z` → bbox quantised to a tile → cache key includes the map's version counter (held by the Room DO, bumped on every write) → Cache API lookup → miss: `geom && ST_MakeEnvelope(...)` with limit and optional simplification → cached with ETag. Writes invalidate by changing the key; old entries expire by TTL.

**Layer switch.** Overlays are stored as WGS84 and re-added after the base layer change, in dedicated panes (saved areas, drafts) above tiles. Option A is chosen (D3): the map CRS is swapped to an EPSG:2039 CRS from Proj4Leaflet on `proj4` (D22 supersedes the earlier no-Proj4Leaflet note) with a `TileLayer` subclass overriding `getTileUrl` for govmap's `L/R/C` scheme, and centre/zoom are converted via `CRS.project/unproject`. A tile proxy is not planned; if A proves technically impossible the spike stops and a new decision is raised.

**Degradation.** Client state machine: connecting → open → degraded → offline. Backoff with jitter; on reconnect resync via bounds query; while offline, poll every 10 s and keep drafts locally. Durable Object hibernation and alarms keep presence correct across idle periods.

## 6. Error handling

- All API errors use the shared `ApiError` shape `{code, message, details?}`; 4xx deliberate, 5xx sanitised and logged with request id.
- Validation failures → 422 with reason (including `ST_IsValidReason`). Auth → 401. Conflict → 409 with server copy. Rate limit → 429 with `Retry-After`. Timeout → 504.
- WS: malformed frames → `error` event, connection kept; repeated abuse → close 1008. DB failures inside the DO never crash the socket; the client is told to resync.
- Logging: structured JSON with request id, user id, route; secrets redacted; Workers Logs enabled.

## 7. Security

Better Auth sessions in httpOnly secure cookies; `trustedOrigins` and CORS with explicit origin + credentials; Zod at every boundary; polygon size caps; exact per-user rate limiter; audit log for every mutation and WS draw session; WAF rules on auth routes in production; health endpoints without data exposure.

## 8. Testing

- Unit (Vitest): area calc vs reference polygons, polygon validation rules, RateLimiter window, conflict path, ITM↔WGS84 utilities.
- Integration (`@cloudflare/vitest-plugin`): REST routes with an ephemeral PostGIS; Room DO protocol (join, draft, broadcast, rate-limit error, hibernation-safe presence).
- API contract suite: `hono batch` JSONL (auth → create → bounds → conflict → delete) run in CI against `--runtime workerd`; `hono snapshot`/`hono diff` as a refactor guard.
- E2E (Playwright): two browsers; draw, see ghost polygon, save, toggle layer, conflict dialog.
- Benchmarks: bounds query on 10k polygons with/without GiST; k6 WS + REST load at 10/50/100 users.

## 9. Scope boundaries

In: everything in the brief's sections 1–6, bonus Docker/tests/OpenAPI/benchmarks. Out (design notes only): multi-region sharding of rooms, Queues for audit batching, OpenTelemetry export, offline editing merge beyond rename.

## 10. Decisions log

- Single shared map; room id `default`; no map entity or picker (D11).
- Any signed-in user may edit or delete any area (D12).
- Defaults accepted: draft updates ≤10/s per user, offline polling every 10 s, presence dropped after 60 s, ≤1,000 vertices, names ≤120 chars (D13).
- Out of scope as design notes only: multi-region room sharding, Queues for audit batching, OpenTelemetry export, geometry merge beyond rename, restore-from-trash UI (D14).
- Retention: soft-deleted areas purged after 7 days (D8).
- Rate limiting: exact per-user Durable Object (D5).
- Rooms: one Durable Object per map; sharding by tile documented as an ADR only (D7).
- Two-browser Playwright E2E is in scope (D10).
- govmap imagery is a requirement; option A (CRS swap) chosen, no proxy, no fallback provider (D3).
- Conflicts: server version check + 409; client two-button prompt (D4).
- Cache invalidation by version-stamped keys bumped in the Room DO (D6).
- Local parity: docker-compose with PostGIS + workerd container; no Node port (D9).
- Leaflet **1.9.4**, not 2.0 alpha: 2.0 is ESM-only with breaking API changes and no plugin ecosystem yet; our custom CRS/handler code is written against stable APIs and ported later.
- Proj4Leaflet (D22, 2026-10-12, supersedes the earlier "no Proj4Leaflet" note): use `proj4leaflet` 1.0.2 (last publish 2022-06, targets the unchanged Leaflet 1.x CRS interface) + `proj4` 2.22.0 for the EPSG:2039 CRS instead of inline CRS wiring. Owner's call: Leaflet's custom-CRS extension point is the documented path, and the plugin is the standard way to use it. Known limit: no Leaflet 2 path; revisit if Leaflet 2 is adopted. The `getTileUrl` override for govmap's hex `L/R/C` scheme stays (a documented Leaflet extension point, ~10 lines).
- Hono over Fastify: Workers are fetch runtimes; Hono runs on Node too; official agent skill + CLI.
- Cloudflare over Vercel: Vercel WebSocket beta has a hard per-connection duration cap; Durable Objects give a native coordinator.
- Design system "Grid 4" adopted (D15, 2026-10-12): 4 px base unit, fixed spacing steps, 6 type sizes on the grid, OKLCH ramps used only through semantic tokens with base/hover/active/disabled variants; reasonable exceptions allowed case by case when a 4 px multiple cannot work, documented in the token file. Brief: `docs/design-system-brief.html`.
- HTTP client (D19, 2026-10-12): native `fetch` behind one typed helper (same-origin cookies, Zod-parsed bodies, shared `ApiError` mapping); Hono `hc` RPC client typed from the api's `AppType` once the areas routes exist. No axios/ky; undici/got are Node-only.
- Audit trail (D20, 2026-10-12): `audit_log` stays as a separate append-only table (brief: "log all user actions for audit trail and analytics"; versions are state snapshots with data-retention lifetime, audit rows outlive the data). `payload_hash` dropped; area events reference `(entity_id, version)`. Folding audit into `area_versions` was considered and rejected: it would cover only area mutations and tie audit retention to the purge.
- Database access (D23, 2026-10-12, system-wide): every query goes through the Drizzle query builder. The `sql` tagged template is allowed only as a fragment inside a builder call for a PostGIS expression the builder cannot model, or for a data-modifying CTE chain the builder cannot express (the atomic validate → insert area → insert version write). Never a whole read statement, never string concatenation. Guarded by lint. Ticket 1.7 (M2).
- Session cookie cache (D24, 2026-10-12): Better Auth `session.cookieCache` enabled with a 5-minute lifetime, so signed-in requests inside the window skip the Neon session lookup (one round-trip less per pan/save). Revocation elsewhere lags ≤ 5 min; same-device sign-out is immediate. Scoped to session validity only, unlike the rejected Hyperdrive query cache. Ticket 2.9, lands in T16.
- Draw tool (D25, 2026-10-12, final): the brief's tech stack says "No third-party plugins for the collaborative features"; collaborative drawing is that feature, so the draw tool stays a hand-rolled Leaflet `L.Handler` on Leaflet core. Geoman and Leaflet.Editable were evaluated and are ruled out by that sentence. Pure maths utilities are not plugins: area and self-intersection use `@turf/area` / `@turf/kinks` 7.4.0 on the client; PostGIS stays the authority.
- Font: Inter variable, self-hosted (D16). Primary hue: blue as proposed (D17). Storybook: full scope — foundations + components + a11y gating + vitest browser tests in CI (D18).
